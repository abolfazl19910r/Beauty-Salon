# بسته‌ی ۰ اپلیکیشن — آزمایش پوش (FCM از ایران روی گوشی واقعی)

برنچ: `experiment/push-probe` (از `develop`؛ **merge نشود** — بعد از نتیجه، فقط تصمیم‌ها وارد بسته‌ی ۴ می‌شوند).

## چه چیزی را می‌سنجیم
پوش FCM دو تکه دارد و هر کدام جدا خراب می‌شود:

| تکه | سؤال | ابزار |
|---|---|---|
| سیستم/سرور ایران ← گوگل | سرور به `oauth2.googleapis.com` و `fcm.googleapis.com` می‌رسد و گوگل قبولش می‌کند؟ | `php artisan push:probe check` |
| گوگل ← گوشی | پیام با اپ باز، پس‌زمینه، بسته، بعد از کشتن توسط مدیریت باتری و بعد از ریستارت می‌رسد؟ چقدر دیر؟ | اپ آزمایشی + `push:probe fcm` |

اگر تکه‌ی اول مستقیم جواب نداد، راه دوم Worker کلودفلر است (`fcm-proxy/`)؛ تکه‌ی دوم همیشه خود FCM است.

### چرا سرویس داخلی و ntfy در این بسته نیستند (تصمیم ۲۰۲۶-۱۰-۰۲)
- سرویس‌های داخلی فعال (متریکس که پوشه را جذب کرده، نجوا، پوشفا) روی گوشی‌های دارای Google Play برای رساندن به گوشی از
  FCM استفاده می‌کنند؛ فقط تکه‌ی اول را حل می‌کنند که Worker هم حل می‌کند. متریکس SDK بومی خودش را هم لازم دارد.
- راه بدون گوگل (اتصال مستقیم گوشی به سرور داخلی، مثل ntfy خودمیزبان) سرور مجازی داخل ایران لازم دارد که فعلاً نیست.
  ⚠️ در قطعی اینترنت بین‌الملل (دی–بهمن ۱۴۰۴، اسفند ۱۴۰۴ تا خرداد ۱۴۰۵) FCM و همه‌ی سرویس‌های روی آن قطع‌اند و فقط پیامک
  (و راه بدون گوگل) می‌ماند — یعنی «پوش بدون رسید → پیامک» (تصمیم ۲) ضروری است، نه اختیاری.

## محتوای بسته
| مسیر | چیست |
|---|---|
| `app/` (همین پوشه) | اپ آزمایشی Expo (SDK 57): توکن FCM، ساخت دستور ارسال، لاگ رسیدن و تأخیر، اشتراک نتایج |
| ریشه‌ی پروژه: `app/Console/Commands/PushProbe.php` + `app/Experiments/PushProbe/` | دستور `push:probe` (FCM HTTP v1 با JWT، بدون پکیج اضافه) |
| ریشه‌ی پروژه: `config/push_probe.php` | تنظیمات (فقط از `.env`) |
| `fcm-proxy/` | Worker کلودفلر، فقط در صورت نیاز |
| `FIREBASE_AND_PHONES.md` | ساخت پروژه‌ی Firebase، ساخت APK، تنظیمات A17 و Redmi Note 8 |
| `RESULTS.md` | فرم نتیجه — همین را پر کنید و برگردانید |
| ریشه‌ی پروژه: `tests/Feature/Console/PushProbeCommandTest.php` | ۹ تست دستور (بدون شبکه) |

## ترتیب اجرا
1. **Firebase:** طبق `FIREBASE_AND_PHONES.md` بخش ۱ — خروجی: `google-services.json` (برای اپ) و فایل حساب سرویس (برای سیستم).
2. **APK:** بخش ۲ همان فایل؛ نصب روی هر دو گوشی؛ در اپ «درخواست اجازه» و «گرفتن توکن». زمان گرفتن توکن را در فرم بنویسید.
3. **سیستم (لوکال XAMPP):**
   ```bash
   git checkout experiment/push-probe
   ```
   در `.env`:
   ```
   PUSH_PROBE_FCM_CREDENTIALS=C:/xampp/secrets/mahru-push-probe-sa.json
   ```
   ```bash
   php artisan config:clear
   php artisan push:probe check
   ```
   - ردیف «توکن دسترسی FCM — مستقیم» = **موفق** → راه مستقیم باز است.
   - «اتصال برقرار نشد» یا 403 → `fcm-proxy/README.md` و از این به بعد `fcm-proxy` به‌جای `fcm`.
   - `cURL error 60` روی ویندوز = گواهی‌ها؛ در `php.ini` مقدار `curl.cainfo` و `openssl.cafile` را به فایل `cacert.pem`
     (از curl.se) بدهید و Apache/ترمینال را دوباره باز کنید.
4. **ارسال:** در اپ حالت را انتخاب کنید (برچسب خودکار مثل `A17-بسته` می‌شود)، «فرستادن دستور به سیستم» را بزنید
   (مثلاً به Saved Messages بله)، روی سیستم اجرا کنید:
   ```bash
   php artisan push:probe fcm <توکن> --label=A17-بسته
   php artisan push:probe fcm <توکن> --label=A17-شب --count=8 --interval=3600   # بیکاری طولانی
   ```
   خروجی «پذیرفته شد» یعنی گوگل پیام را گرفت؛ رسیدن را اپ نشان می‌دهد. همه‌ی ارسال‌ها در `storage/logs/push-probe.csv` هم ثبت می‌شوند.
5. **خواندن نتیجه:** اپ را باز کنید؛ پیام‌های داخل سینی خودکار ثبت می‌شوند (ستون «سینی» = وقتی اپ بسته/پس‌زمینه بود رسید،
   با ساعت واقعی رسیدن). اعلان را **قبل از باز کردن اپ پاک نکنید**. پیامی که اصلاً نیامد در لاگ نیست — همین «نرسید» است.
6. «اشتراک نتایج» هر گوشی + فایل `push-probe.csv` + `RESULTS.md` پرشده را برگردانید.

## نکته‌های دقت
- ساعت گوشی و ویندوز هر دو روی «خودکار» باشند؛ تأخیر = ساعت رسیدن روی گوشی − ساعت ارسال روی سیستم (خطای ۱–۲ ثانیه عادی است).
- لوکال شما اینترنت خانگی است نه دیتاسنتر؛ بعد از استقرار، `push:probe check` را یک بار هم روی هاست واقعی اجرا کنید.
- بعد از آزمایش: کلید حساب سرویس را در Google Cloud حذف کنید (بخش ۱، قدم آخر).
